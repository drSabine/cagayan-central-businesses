# Front End

How the React side is organized and how data reaches it. Read this before adding a page or a component. For how things should look and read, see `design.md`.

React 19 and TypeScript, rendered by Inertia 3, built by Vite, styled with Tailwind CSS 4 and shadcn/ui.

## How data reaches a page

There is no API and no client-side store. The controller is the data layer.

1. A controller returns `Inertia::render('capitol/barangays/show', ['profile' => $profileData])`.
2. Inertia sends `profile` as a prop to `resources/js/pages/capitol/barangays/show.tsx`.
3. The page renders it.

To change what is on screen, change the URL or submit a form. Inertia fetches the new props.

| Need | Use |
| :- | :- |
| Data for a page | Props from the controller |
| Filters | `router.get(url, params, { preserveState: true, preserveScroll: true })`, so filters live in the URL |
| Refresh one prop only | `router.reload({ only: ['rankings'] })` |
| A slow panel | `Inertia::defer()` on the server, a skeleton on the client |
| A form | Inertia's `<Form>` component or `useForm` |
| A small standalone request (search suggestions) | `useHttp` from Inertia 3 |
| A link | `<Link href={show(barangay.psgcCode)}>` with Wayfinder |

Do not add Redux, Zustand, React Query, or Axios. Inertia covers these needs.

## Layers inside the front end

- **Page** (`pages/`): receives props, arranges the screen, owns page state such as which tab is open. Pages do not format numbers by hand or fetch data.
- **Component** (`components/`): shows one thing well and is used in more than one place.
- **Primitive** (`components/ui/`): shadcn building blocks such as button, card, dialog, table.
- **Helper** (`lib/`): pure functions, for example `formatPesos()`, `formatPercent()`.

## When to make a component

Do not split a screen into many tiny files. Each file a reader has to open costs time.

- **Start inline.** Write the markup in the page.
- **Extract when it repeats.** If two pages need it, move it to `components/`.
- **Extract when the page gets long.** Over about 200 lines, pull out a section that has a clear name (`RankingsTable`), keeping it in the same file if only this page uses it.
- **Do not wrap for the sake of it.** No component that only passes props through, no one-line wrappers around a `div`, no `index.ts` re-export files.
- **Check before adding.** Look in `components/ui/` and `components/` first. If shadcn has it, add it with `npx shadcn@latest add <name>` instead of writing your own.
- **Folders by feature, only when needed.** Create `components/<feature>/` when a feature has three or more shared components.

## Types

- Every page declares its props:

```tsx
type Props = {
    profile: BarangayProfile;
};

export default function Show({ profile }: Props) { ... }
```

- Shared shapes live in `resources/js/types/` and match the PHP Data object field for field.
- A guarded sales figure is `{ state: 'shown'; value: string } | { state: 'hidden'; reason: HiddenReason }`.

## Rules for numbers

- No metric math in the browser. No sums, averages, rates, ranks, or shares. The server sends finished values.
- Format only: separators, rounding, pesos, percent. Use the helpers in `lib/` so every screen formats the same way. Rounding rules are in `metrics.md`, "Display rounding".
- "Not available" and "hidden" are never shown as `0` or left blank.

## Links and auth

- Never write a URL by hand. Import from `@/routes` (named routes) or `@/actions` (controller actions). Wayfinder generates both.
- Use `<Link>` for navigation, not `<a href>`, so Inertia keeps the page fast.
- How URLs look and where the server redirects is decided on the back end: `architecture.md`, "Clean URLs" and "Redirects". The front end never builds or rewrites a path.

| Need | Use |
| :- | :- |
| A link | `<Link href={show(barangay.psgcCode)}>` |
| A link with filters | `<Link href={index({ query: { year: 2026 } })}>` |
| Go somewhere from code | `router.visit(show(barangay.psgcCode))` |
| Change filters on the current page | `router.get(index(), { year }, { preserveState: true, preserveScroll: true })` |
| A form | `<Form {...store.form()}>`. After it succeeds, the server redirects; do not navigate in `onSuccess`. |
| A file download (CSV, server export) | a plain `<a href={exportCsv().url}>`, because the response is not an Inertia page |
- Public pages never link to a Capitol page, not even to its login (decisions.md, D20).
- **One exception to Wayfinder:** the admin login form posts to its own URL (`usePage().url`), and its routes are named `admin.login*` so they sit in a Wayfinder module no page imports. Any import that holds the login path would put it in the public bundle.
- The server decides access. Hiding a button in React protects nothing; the route must check it.
- Logout is a `POST`. The Wayfinder route carries the method, so `<Link href={logout()} as="button">` is enough.

## Performance

- **Pages are split automatically.** Inertia's Vite plugin loads each page file on demand, so the login page does not download the dashboard.
- **Load heavy libraries lazily.** The map (MapLibre) and charts (Recharts) are large. Load them with `React.lazy` inside the components that use them, and show a skeleton while they load.

```tsx
const BarangayMap = lazy(() => import('@/components/map/barangay-map'));

<Suspense fallback={<Skeleton className="h-96" />}>
    <BarangayMap areas={areas} />
</Suspense>
```

- **Keep props small.** Ask the server for what you show, not everything that exists.
- **Prefetch likely next pages** with `<Link prefetch>` on main navigation.
- **Paginate long lists** on the server. Never render thousands of rows.
- **The React Compiler is on**, so `useMemo` and `useCallback` are rarely needed. Add them only after measuring a slow render.
- **No runtime calls to third parties,** with one exception: the map's basemap from OpenFreeMap, which is optional (see "The map"). Map shapes always come from our own server.

## The map

MapLibre GL JS through `react-map-gl`. Always import from `react-map-gl/maplibre`; the default import is the Mapbox build, which is paid.

```tsx
import Map, { Layer, Source } from 'react-map-gl/maplibre';
import 'maplibre-gl/dist/maplibre-gl.css';
```

- **Shapes** come from our server as GeoJSON props and are drawn with `<Source type="geojson">` and a `fill` `<Layer>`. Fill colors come from the `--map-*` tokens.
- **Basemap:** OpenFreeMap `positron` (`https://tiles.openfreemap.org/styles/positron`), chosen because it is quiet and lets the choropleth stand out. No key, no account.
- **Offline fallback:** if the style cannot be fetched, the map uses a plain background style and the shapes still draw. Check this before every demo with the network off.

```tsx
const OFFLINE_STYLE = {
    version: 8,
    sources: {},
    layers: [{ id: 'background', type: 'background', paint: { 'background-color': mapColor('--muted') } }],
} as const;

async function loadMapStyle() {
    try {
        const response = await fetch('https://tiles.openfreemap.org/styles/positron');
        return response.ok ? await response.json() : OFFLINE_STYLE;
    } catch {
        return OFFLINE_STYLE;
    }
}
```

- `mapColor()` reads a token from `app.css` and returns a color MapLibre accepts, because map layers cannot use Tailwind classes. Add it to `lib/` with the first map, and use it for every map color. Never a hex value.
- The map component lives in `components/map/` and is loaded with `React.lazy` (see "Performance").
- The map is never the only way to reach a barangay. A list or search does the same job (`design.md`).
- **The province map is different.** `components/province-map.tsx` is a plain SVG of the 29 towns or the 49 Tuguegarao barangays, drawn from the files in `data/boundaries` that are bundled at build time. Pages use `LazyProvinceMap` (`components/lazy-province-map.tsx`), which loads it with `React.lazy` in the browser only and shows a skeleton until then, because a lazy component cannot finish during server rendering. It carries no business data, so it needs no props from the server. Use it for illustration and as a place picker beside a real control, never in place of the MapLibre map.

## Charts

Recharts through shadcn's Chart component (`components/ui/chart.tsx`). It gives tooltips and legends that match the theme, and colors from the `--chart-*` tokens.

- Use `ChartContainer` with a `ChartConfig` that names each series and its token color (`var(--chart-1)`). Never a hex value.
- Shared chart wrappers go in `components/charts/`.
- Every chart has a table version a click away (`design.md`).
- Docs: https://ui.shadcn.com/docs/components/chart

## PDF export

`@react-pdf/renderer` builds the PDF in the browser from the page's own props.

- **Templates** live in `resources/js/pdf/`, one file per document, for example `pdf/barangay-brief.tsx`.
- **Its own layout system.** A template uses `Document`, `Page`, `View`, `Text`, and `StyleSheet` (flexbox). Tailwind classes, shadcn components, and Recharts do not work inside a PDF. If a brief needs a chart, draw it with the library's `Svg` elements and ask first.
- **Same data as the screen.** Build the PDF only from the props the page already received. Never fetch extra data for it (privacy-rules.md, P11).
- **The "Simulated data" label** is on every PDF with business records.
- **Load it only on click,** because the library is large:

```tsx
async function downloadBrief(brief: BarangayBrief) {
    const [{ pdf }, { default: BriefPdf }] = await Promise.all([
        import('@react-pdf/renderer'),
        import('@/pdf/barangay-brief'),
    ]);
    const blob = await pdf(<BriefPdf brief={brief} />).toBlob();
    const link = document.createElement('a');
    link.href = URL.createObjectURL(blob);
    link.download = `brief-${brief.psgcCode}.pdf`;
    link.click();
    URL.revokeObjectURL(link.href);
}
```

## Every data view has these states

| State | Show |
| :- | :- |
| Loading | A skeleton the same size as the content |
| Empty | What is missing and what to do next |
| Not available | "Not available" |
| Hidden | "Hidden to protect individual businesses" |
| Error | A short message and a way to retry |

The exact words are in `privacy-rules.md`, "Words on screen".

## Files and names

- File names are kebab-case: `barangay-profile.tsx`, `use-filters.ts`.
- Components are PascalCase. Hooks start with `use`.
- One shared component per file. Small helpers used only by that component stay in the same file.
